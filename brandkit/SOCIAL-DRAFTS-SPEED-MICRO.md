## Speed · selection criteria

**S1 — price vs clock**
```
humans shop price
agents shop finality

if the receipt isn't on-chain before the next job starts, that marketplace doesn't exist for them
```

**S2 — survival at a cent**
```
a person will wait a week for a check and complain

an agent doesn't complain — it drops the counterparty and takes the next open job

speed isn't a feature
it's survival at a cent
```

**S3 — loop budget**
```
at $0.01 a job, waiting for a human to "approve" the payout costs more than the job

settlement has to clear before the next claim
or the agent just routes around you
```

**S4 — no billing cycle**
```
a cent doesn't leave room for a billing cycle

escrow → deliver → settle has to finish inside the agent's loop
not after the weekend
```

## Micro-cent · job market

**M1 — theater filter**
```
an open board of jobs at a cent only works if claim is free and settlement is automatic

budget already escrowed
first delivery that clears gets paid
everything else is theater
```

**M2 — two-line punch**
```
$0.01 jobs die in human settlement

they live in trustless escrow that clears before the next job
```

**M3 — earn-first (pair with escrow)**
```
a $0 wallet can earn before it ever funds

the budget was already escrowed by the buyer
claim is free — delivery is what gets paid
```

## Trustless escrow

**E1 — no middle bag**
```
buyer locks USDC
seller delivers
chain settles — or refunds on timeout

nobody in the middle holding the bag
that's what trustless hire actually means
```

**E2 — not slow by nature**
```
trustless escrow isn't slow by nature

lock → deliver → settle (or refund on timeout)
no inbox, no invoice, no "accounts payable"

that's the only way $0.01 jobs stay solvent
```

**E3 — two settlement shapes**
```
jobs that need a delivery → escrow, settle when the work lands
calls that need an answer now → pay-per-call, instant

same USDC
same receipts
two settlement shapes, one economy
```

**E4 — instant rail**
```
not every agent job wants a 24h escrow window

some just need pay-per-call settlement that finishes before the next request starts

that's what instant rails are for
```

## Sui

**U1 — move value constantly**
```
small amounts, high frequency, parties that don't know each other

that's not a "store value" chain problem
that's a move-value-constantly problem

Sui is where that job market fits
```

**U2 — economics of a cent**
```
you can't run a micro-cent agent job market on rails that charge more than the job to settle

cheap USDC moves + trustless escrow on Sui is what makes $0.01 work economically
```

**U3 — full thesis (anchor + micro + Sui)**
```
a person picks a marketplace because the price felt right

an agent picks one because a $0.01 escrow job settled — trustlessly — before its next claim started

that loop only stays cheap on a chain built to move small USDC fast
```

## Receipts / models (adjacent, same bank)

**R1**
```
"we agreed" doesn't scale past one counterparty

a receipt is what trust looks like once you stop needing anyone to remember
```

**R2**
```
the hard part stopped being "can it think"

it's "can two of them owe each other money and both walk away sure of the number"

that's not a model problem
```

**R3 — gap**
```
agents can already think for fractions of a cent

they still can't get paid for it without a middleman who has to "trust" both sides

that's the gap
```
